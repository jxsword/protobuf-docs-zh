本主题涵盖两个方面：一般性的平台支持变更，以及正针对 22.x 发布（release）系列考虑的 C++ 专项变更。

## 平台支持变更 {#platform-changes}

我们已在文档的[此章节](/programming-guides/proto2#platforms)中添加了关于我们所支持平台的指引。该章节目前涵盖 C++ 与 PHP，未来可能会扩展，加入其他平台的相关信息。

## 官方 C++ 支持矩阵 {#cpp-support-matrix}

随着本公告前面提到的、采用 Google 官方[基础 C++ 支持政策](/programming-guides/proto2#platforms)这一政策的落实，我们的 [C++ 编译器与工具链支持矩阵将发生变化](https://github.com/google/oss-policies-info/blob/8067c719150dfec6a836dd82230c5eb0ba11acd7/foundational-cxx-support-matrix.md)。

## C++ 变更 {#cpp-changes}

在[新的主版本与破坏性变更（breaking change）政策](/news/2022-07-06)公告发布之后，我们计划对 C++ 进行主版本升级。从 22.x 发布系列开始，我们计划对我们发布的产物（asset）做出一些变更。

以下章节概述了我们计划纳入 Protobuf 22.0 发布的破坏性变更集合。请注意，计划可能会变化，而且也确实会变化。这些是需要留意的潜在破坏性变更，但它们未必会在这一特定发布中发生，也可能根本不会发生。

### 新增 C++20 支持 {#c20-support}

由于 C++ 语言新增了一些关键字，即使你目前并未使用 C++20，为 C++20 添加支持对你的项目而言也是一项破坏性变更。

针对这一问题、仅在特定编译器模式下有条件地更改名称的缓解措施，会破坏那些需要支持多种语言标准的项目。

### 停止支持 C++11 {#c11-support}

按照我们的 [C++ 支持政策](https://opensource.google/documentation/policies/cplusplus-support#4_c_language_standard)，我们计划停止支持 C++11。这是一项破坏性变更。

### 停止支持 Autotools {#autotools}

按照我们的[构建系统支持政策](https://opensource.google/documentation/policies/cplusplus-support#3_build_systems)，我们计划停止支持 autotools。这是一项破坏性变更。在停止支持 autotools 之后，Protobuf 将只支持 CMake 与 Bazel。

### 停止支持 PHP <7.4 {#php-74}

按照我们的 [PHP 支持政策](https://cloud.google.com/php/getting-started/supported-php-versions)，我们计划停止支持已到生命周期终点（EOL）的 PHP 版本。这不被视为破坏性变更，因为这些版本在更广泛的生态系统中已经到达生命周期终点。

### 新增 Abseil 依赖 {#abseil-dep}

为了缩小 Protobuf 在 Google 内部版本与开源（OSS）版本之间的差异，并简化我们自己的项目，我们计划正式依赖 Abseil。假以时日，我们计划开始在公共 API 中使用 Abseil 类型，但仅仅添加这一依赖就已是一项破坏性变更。

### 停止发布语言专属的源码分发包 {#lang-specific-distros}

为了减少对 autotools 的依赖，并尽量减少我们发布的产物数量，我们计划停止在 [GitHub 发布页面](https://github.com/protocolbuffers/protobuf/releases)上发布语言专属的源码分发包。我们建议用户改为下载由 GitHub 在该发布页面上自动生成的[源码分发包](https://github.com/protocolbuffers/protobuf/releases)。

### 将 Maven 候选发布产物名称改得更符合惯例 {#idiomatic}

在 22.0 中，我们计划重命名 Maven 产物，将候选发布（release candidate）前缀从“rc-”改为“RC”。
