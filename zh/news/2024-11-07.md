以下各节介绍计划在 v30 发布（release）中实施的破坏性变更（breaking change），
v30 预计于 2025 年第一季度推出。其中还包含一些并非破坏性、但可能需要你采取
行动的变更。这些内容是对 [10 月 2 日新闻](/news/2024-10-02)所述内容的补充。

以上描述的是我们预期的实现方式，但鉴于软件天然的灵活性，其中部分变更可能
不会落地，也可能与本主题中的描述有所出入。

## 在 Arena 上清理 oneof 消息后引入 ASAN 毒化

此变更为使用 Arena 的 C++ Protobuf 消息（message）增加了一项强化检查。
在 Protobuf arena 上分配的 oneof 消息，现在会在调试模式下被清理，并在
ASAN 模式下被毒化。调用 clear 之后，再试图使用该内存区域，将在 ASAN 中
作为 use-after-free 错误引发崩溃。

该实现[要求 C++17](/news/2024-10-02#drop-cpp-14)。

## Python map 字段的 setdefault 行为变更

从 v30 开始，对 `ScalarMap` 而言，`setdefault` 的行为将类似于 `dict`，
区别在于键（key）与值（value）都必须被设置。对 `MessageMaps` 而言，
`setdefault` 将被拒绝。

## 移除已弃用的 py_proto_library 宏

`protobuf.bzl` 中已弃用（deprecated）的内部 Bazel 宏 `py_proto_library`
将在 v30.x 中移除。

应改用官方的 `py_proto_library`：自 v29.x 起，它将被移入 Protobuf 的
`bazel/py_proto_library`。在 v29.x 之前，该实现位于 `rules_python` 中。

## Python 嵌套消息类的 \_\_qualname\_\_ 包含外层消息名称

Python 嵌套消息类的 `__qualname__` 现在包含外层消息的名称。在 v30 之前，
对嵌套消息而言，`__qualname__` 与 `__name__` 的结果相同，即不包含
外层消息名称。

例如：

```python
message Foo {
  message Bar {
    bool bool_field = 1;
  }
}
nested = test_pb2.Foo.Bar()
self.assertEqual('Bar', nested.__class__.__name__)
self.assertEqual('Foo.Bar', nested.__class__.__qualname__) # 此前为 'Bar'
```

## 停止提供 C++ CocoaPods 发布

在 v30 中，我们将停止提供 C++ CocoaPods 发布，它自 v4.x.x 起就已损坏。
C++ 用户应改为直接使用我们的
[GitHub 发布页](https://github.com/protocolbuffers/protobuf/releases)。

## Ruby 与 PHP 在 JSON 解析中的错误

v30 将按照 [JSON 规范](https://protobuf.dev/programming-guides/json/)，
修复数值字段中字符串的 JSON 解析不符合规范的问题。

此修复不会伴随主版本（version）提升，但 Ruby 和 PHP 现在会对数值字段中的
非数字字符串（例如 ""、"12abc"、"abc"）抛出错误。v29.x 将针对这些错误情形
给出警告。
