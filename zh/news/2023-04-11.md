## 语法反射（reflection）的弃用 {#deprecation}

v23 将弃用通过反射检查语法版本的能力。该弃用（deprecation）将在构建时以警告的形式体现。该能力将在未来的发布（release）中移除。

## 在 C++ 中添加对 ctype=CORD 的支持 {#cord}

v23 将为单数（singular）`bytes` 字段（field）（包括 `oneof` 字段）添加 `ctype=CORD` 支持，用于指定数据应使用
[`absl::cord`](https://github.com/abseil/abseil-cpp/blob/master/absl/strings/cord.h)
而不是 `string` 来存储。如果开源社区有足够的需求，未来的发布可能会为单数 `string` 字段类型以及 `repeated` `string` 和 `byte` 字段添加支持。

`ctype=CORD` 对扩展（extension）不会有任何影响。

你可以使用字段选项（option）来添加这一支持：

```proto
optional bytes foo = 25 [ctype=CORD];
```

## 选项保留性（retention） {#retention}

选项现在有了*保留性*的概念，用于控制一个选项是否保留在生成代码（generated code）中。选项默认始终具有*运行时保留性（runtime retention）*，也就是说，选项会保留在生成代码中，因而在运行时可以在生成的描述符池（descriptor pool）中看到它们。不过，你现在可以设置 `retention = RETENTION_SOURCE`，以指定某个选项（或选项内的字段）不得在运行时保留。这称为*源码保留性（source retention）*。

设置保留性的写法如下：

```proto
extend google.protobuf.FileOptions {
  optional int32 source_retention_option = 1234
      [retention = RETENTION_SOURCE];
}
```

它也可以设置在普通字段上，此时仅当该字段出现在选项中时才会生效：

```proto
message OptionsMessage {
  optional int32 source_retention_field = 1 [retention = RETENTION_SOURCE];
}
```

更多信息请参阅[选项保留性](/programming-guides/proto3#option-retention)。

## 停止支持 Bazel <5.3 {#bazel}

v23 将停止支持 Bazel 4。Protobuf 将继续支持 Bazel 5 LTS，最低要求版本为 Bazel 5.3。这遵循
[基础 C++ 支持政策（Foundational C++ Support Policy）](https://opensource.google/documentation/policies/cplusplus-support#build_systems)
中描述的构建支持政策，也体现在
[基础 C++ 支持（Foundational C++ Support）](https://github.com/google/oss-policies-info/blob/main/foundational-cxx-support-matrix.md)
所列的版本中。
