以下公告专门针对 25.x 版本（version），该版本于 2023 年 11 月 1 日发布（release）。
按时间顺序呈现的信息请参阅 [新闻](/news)。

## Python 破坏性变更（breaking change）

在 v25 中，[`message.UnknownFields()`](https://googleapis.dev/python/protobuf/latest/google/protobuf/message.html#google.protobuf.message.Message.UnknownFields)
将在纯 Python 与 C++ 扩展中被弃用（deprecated），并将在 v26 中移除。请使用
`unknown_fields.py` 中新的
[`UnknownFieldSet(message)`](https://googleapis.dev/python/protobuf/latest/google/protobuf/unknown_fields.html)
支持作为替代。

## μpb 迁入 Protobuf Git 仓库

自 v25 发布起，μpb 现已迁移至
[Protobuf 仓库](https://github.com/protocolbuffers/protobuf)，不再位于其
[此前所在的独立仓库](https://github.com/protocolbuffers/upb)。此后所有 μpb 的
开发都只会在新位置进行。

两个仓库的合并将简化并加快我们的开发流程，因为不再需要在 Protobuf 与 μpb 之间
更新固定的版本依赖。对 μpb 的更改现在会立即在 Protobuf 代码中生效，反之亦然，
无需手动升级步骤。

我们预计大多数用户几乎无需为此变更采取任何行动。μpb 是我们 Ruby、PHP 与 Python
实现背后的引擎，但除非你有直接引用 μpb 的代码，否则很可能不会注意到这一变更。

如果你在 Bazel 项目中引用 μpb，则需要将 μpb 引用更新为指向 Protobuf（例如，把
`@upb` 替换为 `@com_google_protobuf`）。我们会保持 μpb 的文件路径与 Bazel 目标
不变，以尽量减少所需的额外改动，但有两个例外：

-   `upbc` 目录已更名为 `upb_generator`。
-   μpb 的顶层 `BUILD` 文件已移入 `upb` 目录。因此，例如对 `@upb//:reflection`
    的引用现在应写作 `@com_google_protobuf//upb:reflection`。

## 对 Java 生成代码（gencode）下毒

我们正在向 25.x 分支合入一个变更，该变更会对在
[3.21.7 版本发布](https://github.com/protocolbuffers/protobuf/releases/tag/v21.7)
之前创建的 Java 生成代码下毒。随后，我们会将 3.21.7 至 3.25.5 的所有 Java
Protobuf 版本标记为易受
[footmitten CVE](https://github.com/protocolbuffers/protobuf/security/advisories/GHSA-h4h5-3hr4-j3g2)
影响。

在该变更以补丁形式合入后，除非你设置系统属性
"`-Dcom.google.protobuf.use_unsafe_pre22_gencode`"，否则 protobuf 将从
[`makeExtensionsImmutable`](https://protobuf.dev/reference/java/api-docs/com/google/protobuf/GeneratedMessage.html#makeExtensionsImmutable\(\))
方法抛出 `UnsupportedOperationException`。如果你无法立即更新代码，使用该系统属性
可以为你争取一些时间，但应将其视为短期权宜之计。
