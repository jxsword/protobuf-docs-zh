以下公告专门针对 22.x 版本（version），该版本于 2023 年 2 月 16 日发布（release）。按时间顺序呈现的信息请参阅
[新闻](/news)。

### 将 Maven 候选发布版本（release candidate）的构件（artifact）名称改为更符合习惯的形式 {#idiomatic}

在 22.0 中，我们计划重命名 Maven 构件，将候选发布版本前缀从 “rc-” 改为 “RC”。

### 添加 Abseil 依赖 {#abseil-dep}

为了缩小 Protobuf 在 Google 内部版本与开源（OSS）版本之间的差异，并简化我们自己的项目，我们计划正式引入对 Abseil 的依赖。随着时间推移，我们计划开始在公开 API 中使用 Abseil 类型，但仅仅添加这一依赖本身就是一项破坏性变更（breaking change）。

### 停止支持 PHP <7.4 {#php-74}

按照我们的
[PHP 支持政策](https://cloud.google.com/php/getting-started/supported-php-versions)，
我们计划停止支持已达生命周期终点（EOL）的 PHP 版本。由于这些版本在整个生态系统中早已到达生命周期终点，因此这不被视为破坏性变更。

### 停止支持 Autotools {#autotools}

按照我们的
[构建系统支持政策](https://opensource.google/documentation/policies/cplusplus-support#3_build_systems)，
我们计划停止支持 autotools。这是一项破坏性变更。在停止支持 autotools 之后，Protobuf 将仅支持 CMake 和 Bazel。

### 停止支持 C++11 {#c11-support}

按照我们的
[C++ 支持政策](https://opensource.google/documentation/policies/cplusplus-support#4_c_language_standard)，
我们计划停止支持 C++11。这是一项破坏性变更。

### 添加 C++20 支持 {#c20-support}

由于 C++ 语言新增了一些关键字，即使你目前并未使用 C++20，为 C++20 添加支持对你而言也是一项破坏性变更。

为此采取的缓解措施——仅在特定编译器模式下有条件地更改名称——会破坏那些支持多种语言标准的项目。

## C++ 变更 {#cpp-changes}

继我们宣布
[新主版本与破坏性变更政策](/news/2022-07-06)
之后，我们计划提升 C++ 的主版本号。从 22.x 发布系列开始，我们计划对所发布的产物（asset）做出一些变更。

以下各节概述了我们计划纳入 Protobuf 22.0 发布中的那组破坏性变更。请注意，这些计划可能并且确实会发生变化。它们是需要留意的潜在破坏性变更，但可能不会在此次发布中发生，也可能根本不会发生。
