以下各节介绍 v38 发布（release）中计划实施的破坏性变更（breaking change），v38 预计于 2027 年第一季度发布。这些内容描述了我们所预期的变更实现方式，但由于软件本身具有灵活性，其中部分变更可能不会最终落地，或与本主题中的描述有所出入。

## Bazel 的变更 {#bazel}

### 停止支持 Bazel 8

本次发布将不再把 Bazel 8 作为最低支持版本，而是将其提升至 Bazel 9，依据是[基础 C++ 支持矩阵（Foundational C++ Support Matrix）](https://github.com/google/oss-policies-info/blob/main/foundational-cxx-support-matrix.md)。作为该项变更的一部分，对旧式 `WORKSPACE` 构建的支持将被移除，并要求使用 Bzlmod（`MODULE.bazel`）。

### 移除已弃用的 API

#### Internal_py_proto_library

**API**：`internal_py_proto_library()`

**替代方案**：`py_proto_library()`

### 移除已弃用的标志

**strict_proto_deps**

移除 `--strict_proto_deps` 标志。Bazel 构建规则将始终对 proto 文件（proto file）强制执行严格的依赖检查。你应确保自己的 `proto_library()` 目标遵循正确的分层。

**cc_proto_library_header_suffixes**

移除 `--cc_proto_library_header_suffixes` 标志。目前，`--cc_proto_library_header_suffixes` 标志允许用户设置我们的 C++ 代码生成将要生成哪些头文件后缀。其默认值为 \[".pb.h"\]，但用户也可以将其设置为其他值，使 `cc_proto_library()` 预期其他后缀。

**cc_proto_library_source_suffixes**

移除 `--cc_proto_library_source_suffixes`。默认后缀仍为 `.pb.cc`，用户将不能再设置要生成的额外源文件后缀。

**翻转 strict_string_public_imports 标志的默认值**

将 `--strict_string_public_imports` 标志的默认值翻转为开启。这会针对 proto_library 目标的 `exports` 属性，对 .proto 文件中的 `import public` 语句实施严格检查。如果某个 .proto 文件对未在 `exports` 中声明的依赖使用了 `import public`，构建将会失败。

### 用 rules_python 替换 system_python

将 `@system_python` 仓库（repository）和工具链替换为标准的 `rules_python` 工具链，并彻底移除 `@system_python`。

在 `MODULE.bazel` 或 `WORKSPACE` 文件中引用了 `@system_python` 的下游（downstream）使用方（例如引用 `@system_python//:python_headers`、`@system_python//:pip.bzl` 或 `@system_python//:interpreter`），必须在升级之前迁移到 `rules_python` 的等价物，因为 Protobuf 将不再提供 `@system_python`。

## C++ 的变更 {#cpp}

C++ 的主版本将从 7.37.x 升至 8.38.x。

### 添加 `[[nodiscard]]`

移除 `PROTOBUF_FUTURE_ADD_NODISCARD` 宏。此前，多个 Protobuf API 已引入 `[[nodiscard]]`，用于对常见的 API 误用产生编译期警告，避免易错陷阱。本次变更移除了这个临时的过渡标志宏，使 `[[nodiscard]]` 注解永久生效。

### 翻转 proto_h 标志的默认值

将 proto_h 的默认值翻转为 True。默认情况下，会生成 .proto.h 文件。

### 移除已弃用的 API

我们移除这些 API，是因为它们与开放式枚举（open enum）不兼容。

#### `Reflection::GetEnum()`

**API**：`Reflection::GetEnum()`

**替代方案**：`Reflection::GetEnumValue()`

#### `Reflection::GetRepeatedEnum()`

**API**：`Reflection::GetRepeatedEnum()`

**替代方案**：`Reflection::GetRepeatedEnumValue()`

### 通用服务选项

禁用 `cc_generic_services` 的代码生成，因为通用服务（generic services）自引入之日起就已被弃用。你可以通过设置 protoc 标志 `--allow_legacy_generic_services` 来恢复旧有行为。该标志将在未来某个包含破坏性变更的发布中被移除。有关弃用的缘由，请参阅[关于通用服务的设计决策](/design-decisions/insertion-points-and-generic-services#generic-services)。

## Java 的变更 {#java}

Java 的主版本将从 4.37.x 升至 5.38.x。不过，这并不是 API 层面的破坏性变更，并且在本次发布中，我们**不会**破坏生成代码（generated code）的兼容性，也不会对来自 3.x.x 的旧生成代码设置毒丸（poison pill）。此次版本号提升只是为了表明，本次发布包含了一些值得注意的行为变更。

### OneofDescriptor

将校验 `oneof` 不得与其他任何描述符（descriptor）重名。这消除了命名冲突的风险——此类冲突可能会造成破坏。

### 将内部字段标记为 transient

将消息（message）实现中的若干字段标记为 transient，使其在遵循 transient 标记的格式中不被序列化——GSON 尤其如此。在没有使用 GSON 随附的某个 Protobuf 类型适配器（type adapter）时，请不要在生成的 Protobuf 类上使用 GSON。

### UTF-8 校验特性

在所有版次（Editions）中，针对 string 扩展（extension）遵循 UTF-8 校验特性（feature）。

### 通用服务选项

禁用 `java_generic_services` 的代码生成，因为通用服务自 2010 年起就已被弃用。你可以通过设置 protoc 标志 `--allow_legacy_generic_services` 来恢复旧有行为。该标志将在未来某个包含破坏性变更的发布中被移除。有关弃用的缘由，请参阅[关于通用服务的设计决策](/design-decisions/insertion-points-and-generic-services#generic-services)。

## Objective-C 的变更 {#objectivec}

弃用对 Objective-C 的支持。在 37.x 这一长期支持发布中，Objective-C 将持续获得支持，直至 2027 年第四季度。反馈可提交至[GitHub 议题](https://github.com/protocolbuffers/protobuf/issues/30118)。

## Python 的变更 {#python}

Python 的主版本将从 7.37.x 升至 8.38.x。

### 停止支持 Python 3.10

本次发布将不再以 Python 3.10 作为最低支持版本，而是将其提升至 3.11，依据是[基础 Python 支持矩阵（Foundational Python Support Matrix）](https://github.com/google/oss-policies-info/blob/main/foundational-python-support-matrix.md)。

### 不可变的 `GetOptions()`

描述符对象（如 `Descriptor`、`FieldDescriptor` 和 `FileDescriptor`）上的 `GetOptions()` 方法现在返回不可变的选项（option）消息。尝试修改返回的选项对象会抛出 `FrozenInstanceError`。

### 对无法识别的类型返回 `NotImplemented`

在与无法识别的类型进行相等性比较时，Python Protobuf 的 C++ 实现与 upb 实现此前会直接返回 `False`。现在它们会返回 `NotImplemented`，以遵循标准的 Python 比较行为，并允许在另一个操作数上进行反射比较（reflected comparison）。

### `RepeatedContainer.pop()`

在 upb 实现中，对可重复字段（repeated field）容器调用 `pop()` 时，如果索引大于或等于容器的长度，现在会抛出 `IndexError`，而不是钳制到最后一个元素。

### 将 `\?` 解码为 `?`

通过将 `\?` 转义序列解码为 `?`，使 Python 的 textproto 解码器与 C++ 和 Java 实现保持一致。

### 启用 NX 与 ASLR

启用将 NX 与 ASLR 安全特性标志向下传递至目标仓库的机制。

### 解析 JSON 布尔值

修复了一个缺陷：此前 Python 的 JSON 解析器会把 JSON 布尔值解析到 int 或 float/double 类型的 Protobuf 字段中。

### 通用服务选项

禁用 `python_generic_services` 的代码生成，因为通用服务自 2010 年起就已被弃用。你可以通过设置 protoc 标志 `--allow_legacy_generic_services` 来恢复旧有行为。该标志将在未来某个包含破坏性变更的发布中被移除。有关弃用的缘由，请参阅[关于通用服务的设计决策](/design-decisions/insertion-points-and-generic-services#generic-services)。

## PHP 的变更 {#php}

### 停止支持 PHP 8.2

本次发布将不再以 PHP 8.2 作为最低支持版本，而是将其提升至 8.3，依据是[基础 PHP 支持矩阵（Foundational PHP Support Matrix）](https://github.com/google/oss-policies-info/blob/main/foundational-php-support-matrix.md)。

### UTF-8 有效性

在 upb json 解码器中强制执行 UTF-8 有效性校验。

## 一致性测试 {#conformance-tests}

Protobuf 项目维护着一套庞大的一致性测试（conformance test）套件，以确保各语言与各运行时（runtime）之间的行为保持一致。作为我们对规范符合性与互操作性的持续承诺的一部分，我们正在积极处理并落实多项一致性测试更新。

由于测试套件覆盖面很广，有关哪些具体一致性测试与行为将发生变化等详细信息，将在发布说明（release notes）中公布。
