以下章节介绍 v34 发布中计划实施的破坏性变更（breaking change），该发布预计于 2026 年第一季度推出。这些内容描述了我们所预期的变更实现方式，但由于软件本身具有灵活性，其中部分变更可能不会最终落地，或与本主题中的描述有所出入。

## C++ 的变更 {#cpp}

C++ 将随 7.34.0 发布把主版本号提升至 7。6.33 将是 6.x 系列的最后一个次版本发布。

### 移除 Future 宏 {#cpp-remove-macros}

以下宏是为分阶段推行破坏性变更而引入的，它们将被移除，其行为将成为默认行为：

*   `PROTOBUF_FUTURE_RENAME_ADD_UNUSED_IMPORT`
*   `PROTOBUF_FUTURE_REMOVE_ADD_IGNORE_CRITERIA`
*   `PROTOBUF_FUTURE_STRING_VIEW_DESCRIPTOR_DATABASE`
*   `PROTOBUF_FUTURE_NO_RECURSIVE_MESSAGE_COPY`
*   `PROTOBUF_FUTURE_REMOVE_REPEATED_PTR_FIELD_ARENA_CONSTRUCTOR`
*   `PROTOBUF_FUTURE_REMOVE_MAP_FIELD_ARENA_CONSTRUCTOR`
*   `PROTOBUF_FUTURE_REMOVE_REPEATED_FIELD_ARENA_CONSTRUCTOR`

### RepeatedPtrField 的新布局 {#cpp-repeatedptrfield-layout}

`RepeatedPtrField` 将过渡到一种新的内部元素布局：元素将存储在预先分配的连续内存块中，类似 `std::deque`。这会给部分 API 的拷贝/移动语义带来一些变化，部分 `UnsafeArena` API 也可能变得与其 arena 安全版本功能等价，并被弃用（deprecated）。

### RepeatedField::Get 与 RepeatedPtrField::Get 上的 MSB 加固检查 {#cpp-repeatedfield-get-hardening}

Protobuf 将通过对可重复字段（repeated field）的访问添加全面的边界检查来进行加固，以防范越界（OOB）错误。

<a id="cpp-remove-arena-pointers"></a>

### 从 Repeated/Map 字段中移除支持 arena 的构造函数 {#cpp-remove-arena-ctors}

`RepeatedField(Arena*)`、`RepeatedPtrField(Arena*)` 和 `Map(Arena*)` 构造函数将被删除。

### 移除已弃用的 API {#cpp-remove-apis}

本次发布将移除以下公共运行时（runtime）API；这些 API 被标记为弃用至少已跨越一个次版本或主版本发布周期，且现已过时或已有替代方案。

#### AddUnusedImportTrackFile() 与 ClearUnusedImportTrackFiles()

**API：** `AddUnusedImportTrackFile()`、`ClearUnusedImportTrackFiles()`

**替代方案：** `AddDirectInputFile()` 和 `ClearDirectInputFiles()`

#### 消息差异比较器（message differencer）中的 AddIgnoreCriteria

`PROTOBUF_FUTURE_REMOVE_ADD_IGNORE_CRITERIA` 是为这项破坏性变更而添加的。本次发布将移除该宏。

**API：** `AddIgnoreCriteria()`

**替代方案：** 将裸指针包裹在 `unique_ptr` 中。

#### FieldDescriptor::has_optional_keyword()

**API：** `FieldDescriptor::has_optional_keyword()`

**替代方案：** `has_presence()`

#### FieldDescriptor::label()

**API：** `FieldDescriptor::label()`

**替代方案：** `is_repeated()` 或 `is_required()`

#### FieldDescriptor::is_optional()

**API：** `FieldDescriptor::is_optional()`

**替代方案：** `!is_required() && !is_repeated()`

#### UseDeprecatedLegacyJsonFieldConflicts()

**API：** `UseDeprecatedLegacyJsonFieldConflicts()`

**替代方案：** 无。

### 更严格的名称长度限制 {#cpp-name-limits}

为防范潜在问题，Protobuf 编译器将对符号名称的长度实施更严格的限制，例如字段名（field name）。如果任何字段名的长度 > 2^16，将产生错误。

### 在 CMake 中隐藏私有生成器头文件 {#cpp-cmake-headers}

protoc 生成器头文件将不再由 CMake 安装。这应该不会影响大多数用户。

### 逻辑恒定操作上的 [[nodiscard]] {#cpp-nodiscard}

将为若干逻辑上恒定的 Protobuf API 添加 `[[nodiscard]]`；对于这些 API，不消费返回值往往表明存在 bug。这遵循了 C++ 标准库中常用的模式。

## Python 的变更 {#python}

Python 将随 7.34.0 发布把主版本号提升至 7。6.33 将是 6.x 系列的最后一个次版本发布。

生成代码（gencode）没有变化，并且我们会放宽毒丸（poison pill）检查。对 7.34.x 而言，旧的生成文件不会触发任何警告或错误。

### 错误类型转换为 Timestamp/Duration 时抛出 TypeError {#python-type-error-timestamp-duration}

本次发布将在把错误类型转换为 `Timestamp` 或 `Duration` 时抛出 `TypeError`，而不是 `AttributeError`。

### 拒绝将 bool 赋给 enum 与 int 字段 {#python-reject-bool-enum-int}

本次发布将拒绝使用布尔值设置 enum 或 int 字段。API 将抛出错误，而不是隐式转换这些值。

### 从 json_format 中移除 float_precision {#python-remove-float-precision}

本次发布将从 `json_format` 序列化器中移除已弃用的 `float_precision` 选项（option）。该选项在其他 ProtoJSON 序列化器中并不存在，且语义令人困惑。

### 从 text_format 中移除 float_format/double_format {#python-remove-text-format-options}

本次发布将从 `text_format` 中移除已弃用的 `float_format` 和 `double_format` 选项。这些选项在其他 proto 文本格式（text format）序列化器中不可用。

### 移除已弃用的 API {#python-remove-apis}

本次发布将移除以下公共运行时 API。

#### FieldDescriptor.label

**API：** `FieldDescriptor.label`

**替代方案：** 使用 `is_repeated()` 或 `is_required()`。

## PHP 的变更 {#php}

PHP 将随 5.34.0 发布把主版本号提升至 5。4.33 将是 4.x 系列的最后一个次版本发布。

### 移除已弃用的 API {#php-remove-apis}

本次发布将移除以下公共运行时 API。

#### FieldDescriptor getLabel

**API：** `FieldDescriptor getLabel`

**替代方案：** `isRepeated()` 或 `isRequired()`

#### Google\Protobuf\Field_Kind

**API：** `Google\Protobuf\Field_Kind`

**替代方案：** `Google\Protobuf\Field\Kind`

#### Google\Protobuf\Field_Cardinality

**API：** `Google\Protobuf\Field_Cardinality`

**替代方案：** `Google\Protobuf\Field\Cardinality`

#### Google\Protobuf\Internal\RepeatedField

**API：** `Google\Protobuf\Internal\RepeatedField`

**替代方案：** `Google\Protobuf\RepeatedField`

### JSON 解析更趋严格 {#php-json-parsing}

JSON 解析器将变得更加严格，拒绝若干此前被接受的情况，包括超出范围的值、整数字段传入非整数值、重复的 oneof 字段，以及字符串字段传入非字符串值。JSON 序列化器也将拒绝数值出现 `Infinity` 和 `NaN`。

### 修复默认值被静默忽略的问题 {#php-fix-default-values}

PHP 运行时将被修复，使其遵循 proto2 和版次（editions）中标量字段（scalar field）的默认值（default value），而不是静默忽略这些默认值。

### 类型检查对齐 {#php-type-checking}

纯 PHP（pure-PHP）与 upb-PHP 两种实现的类型检查将对齐。值得注意的是，pure-PHP 将拒绝为字符串字段设置 `null`，从而与 upb-PHP 的行为保持一致。

## Objective-C 的变更 {#objc}

Objective-C 将随 5.34.0 发布把主版本号提升至 5。4.33 将是 4.x 系列的最后一个次版本发布。

部分 `GPB*Dictionary` API 的可空性（nullability）注解将被修正，以标明这些 API 何时可能返回 `nil`。这会使 Swift 代码得到 Swift 的 `Optional<T>`，从而构成破坏性 API 变更。对 Objective-C 调用方而言，该注解修正不太可能对源代码产生任何影响。

### 移除已弃用的 API {#objc-remove-apis}

本次发布将移除以下公共运行时 API。

#### -[GPBFieldDescriptor optional]

**API：** `-[GPBFieldDescriptor optional]`

**替代方案：** 改用 `!required && fieldType == GPBFieldTypeSingle`。

## Bazel 的变更 {#bazel}

### Proto 标志（flag）迁移至 Starlark {#bazel-starlark-flags}

Proto 规则不再读取 `--proto_toolchain_for*` 和 `--proto_compiler`。这些与工具链（toolchain）相关的标志已被弃用，并将在未来被移除。切换到等价的 Starlark 标志是一种短期解决方案：

*   `--@protobuf//bazel/flags/cc:proto_toolchain_for_cc`
*   `--@protobuf//bazel/flags/java:proto_toolchain_for_java`
*   `--@protobuf//bazel/flags/java:proto_toolchain_for_javalite`
*   `--@protobuf//bazel/flags:proto_compiler`

更长期的解决方案是启用 `--incompatible_enable_proto_toolchain_resolution`（这在 Bazel 9 中本来就是默认行为），并使用常规的平台相关机制注册工具链（`MODULE.bazel` 或 `WORKSPACE` 中的 `register_toolchain()`，或 `--extra_toolchains`）。

其余所有 Bazel Proto 标志也已迁移到 Starlark，原生标志将随 Bazel 的下一次发布被弃用。请使用以下 Starlark 标志，以避免将来出现破坏性变更：

*   `--@protobuf//bazel/flags:strict_proto_deps`
*   `--@protobuf//bazel/flags:strict_public_imports`
*   `--@protobuf//bazel/flags:experimental_proto_descriptor_sets_include_source_info`
*   `--@protobuf//bazel/flags/cc:cc_proto_library_header_suffixes`
*   `--@protobuf//bazel/flags/cc:cc_proto_library_source_suffixes`
*   `--@protobuf//bazel/flags:protocopt`

**注意：**在 v34.0 中，`--@protobuf//bazel/flags:protocopt` 被错误地放在了 `--@protobuf//bazel/flags/cc:protocopt` 位置。该标志将被移动到正确位置，并且自 v34.1 起，`cc` 位置将作为一个已弃用的别名保留。不应使用该别名，它将在下一次破坏性变更中被移除。

### 移除已弃用的 ProtoInfo.transitive_imports {#bazel-transitive-imports}

`ProtoInfo` 中已弃用的 `transitive_imports` 字段将被移除。用户应迁移到 `transitive_sources`。

### 移除 protobuf_allow_msvc 标志并继续支持 Bazel+MSVC {#remove-protobuf_allow_msvc}

得益于 Bazel 近期在 Windows 上的改进，我们现在计划继续支持 Bazel+MSVC。`--define=protobuf_allow_msvc` 标志将被移除。

## 其他变更 {#other-changes}

以下是另外一些破坏性变更。

### 未提升主版本号的语言

Java、Ruby、C#、Rust 和 JRuby 在本次发布中不会提升主版本号。
