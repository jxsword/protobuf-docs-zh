我们计划在 v30 中修改面向 C++ 的 Protobuf 调试 API（包括 Protobuf
AbslStringify、`proto2::ShortFormat`、`proto2::Utf8Format`、`Message::DebugString`、`Message::ShortDebugString`、`Message::Utf8DebugString`），
以对由 `debug_redact` 注解的敏感字段（field）进行脱敏（redact）；这些 API 的输出将包含一个随进程而异的随机前缀，因此将无法再被 Protobuf TextFormat 解析器解析。

## 动机

目前，Protobuf 调试 API 会将 proto 中的每个字段打印为人类可读的格式。这可能导致隐私事故：开发者无意间记录了包含敏感字段的 Protobuf 调试输出。

## 如何注解敏感字段

有两种方式可将字段标记为敏感：

*   直接用字段选项（field option）`debug_redact = true` 标记某个字段。

    ```proto
    message Foo {
      optional string secret = 1 [debug_redact = true];
    }
    ```

*   如果你已经通过扩展 `proto2.FieldOptions` 定义了枚举（enum）类型的字段注解，且该注解的某些取值被用于注解你希望脱敏的字段，那么你可以用 `debug_redact = true` 注解这些取值。所有以此类取值注解的字段都将被脱敏。

    ```proto
    package my.package;

    extend proto2.FieldOptions {
      # 既有的字段注解
      optional ContentType content_type = 1234567;
    };

    enum ContentType {
      PUBLIC = 0;
      SECRET = 1 [debug_redact = true];
    };

    message Foo {
      # 不会被脱敏
      optional string public_info = 1 [
        (my.package.content_type) = PUBLIC
      ];
      # 会被脱敏
      optional string secret = 1 [
        (my.package.content_type) = SECRET
      ];
    }
    ```

## 新的调试格式

与现有的调试格式相比，新的调试格式有两项主要差异：

*   由 `debug_redact` 注解的敏感字段会在输出格式中被自动脱敏
*   输出格式将包含一个随进程而异的随机前缀，这使其无法再被 TextFormat 解析器解析。

请注意，无论 proto 是否包含敏感字段，第二项变化都成立；这确保了无论 proto 内容如何，任何调试输出都始终无法被反序列化（deserialization）。
