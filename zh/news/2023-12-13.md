## C++ 破坏性变更

在 v26 中，按照我们的[破坏性变更（breaking change）政策](/news/2022-07-06)和
[版本支持政策](/support/version-support#cpp-tooling)，我们计划对 C++ 进行主版本升级。

以下章节概述了我们计划纳入 Protobuf 26.0 发布（release）的破坏性变更集合。请注意，计划可能会变化，而且也确实会变化。这些是需要留意的潜在破坏性变更，但它们未必会在这一特定发布中发生，也可能根本不会发生。

### 移除 repeated 字段上已弃用（deprecated）的 clear API

以下已弃用的方法将被移除：

*   `RepeatedPtrField::ReleaseCleared()`
*   `RepeatedPtrField::ClearedCount()`
*   `RepeatedPtrField::AddCleared()`

### 移除 C++ 旧式 syntax 描述符（descriptor）API

随着[版次（edition）](/editions)的发布，业务逻辑不再支持 syntax。请改用
[`descriptor.h`](/reference/cpp/api-docs/google.protobuf.descriptor)
中定义的各种特性（feature）辅助方法来查询更有针对性的行为，例如
[`has_presence`](/reference/cpp/api-docs/google.protobuf.descriptor#FieldDescriptor.has_presence.details)，
以便在 C++ 中查询特性。

### 移除已弃用的 syntax 访问器（accessor）

我们计划在 v26 中移除已弃用的 syntax 访问器 `FileDescriptor::Syntax`。我们建议改用 `FileDescriptor::edition` 提供的 getter。

### 移除已弃用的 SupportsUnknownEnumValues 方法

`SupportsUnknownEnumValues` 方法
[已于 2023 年 3 月被弃用](https://github.com/protocolbuffers/protobuf/pull/12129)。
我们计划在 v26 中将其移除。

### 移除 std::string 错误收集器覆盖方法

我们计划移除错误收集器中已弃用的 `std::string` 方法。

## Python 破坏性变更

在 v26 中，按照我们的[破坏性变更政策](/news/2022-07-06)和
[版本支持政策](/support/version-support#python-support)，我们计划对 Python 进行主版本升级。

### 时间戳会进行有效性检查

在 v26 中，系统会检查 `Timestamp` 值是否有效。秒必须位于 [-62135596800, 253402300799] 范围内，纳秒必须位于 [0,
999999999] 范围内。超出这些范围的值将抛出异常。

### 移除已弃用的 syntax 访问器

我们计划在 v26 中移除已弃用的 syntax 访问器 `FileDescriptor.syntax`。我们计划在其位置新增 `FileDescriptor.edition`。

### 移除 UnknownFields 支持

在 v25 中，
[`message.UnknownFields()`](https://googleapis.dev/python/protobuf/latest/google/protobuf/message.html#google.protobuf.message.Message.UnknownFields)
在纯 Python 与 C++ 扩展中已被弃用。我们计划在 v26 中将其移除。请使用
`unknown_fields.py` 中新的
[`UnknownFieldSet(message)`](https://googleapis.dev/python/protobuf/latest/google/protobuf/unknown_fields.html)
支持作为替代。

有关所有这些变更的更多详情将见相应的发布说明。
