## 版次 2024

我们计划于 2025 年第三季度在 32.x 中发布 Protobuf 版次 2024（Edition 2024）。

这些内容描述了我们所预期的变更实现方式，但由于软件本身具有灵活性，其中部分变更可能不会最终落地，或与本主题中的描述有所出入。

有关版次 2024 的更多文档将发布在[版次特性设置（Feature Settings for Editions）](/editions/features)中，其中包括从版次 2023（Edition 2023）迁移的相关信息。

## 现有特性的变更 {#changes}

本节详细介绍默认设置将在版次 2024 中发生变更的现有特性。

### C++ string_type {#string_type}

`string_type` 特性最初随版次 2023 发布，其默认值将在版次 2024 中从 `STRING` 变为 `VIEW`。

有关该特性及其特性值（feature value）的更多信息，请参阅 [`features.(pb.cpp).string_type`](/editions/features#string_type) 和[字符串视图（string view）API](/reference/cpp/string-view)。

## 新特性 {#new-features}

本节详细介绍将在版次 2024 中引入的新特性。

### `enforce_naming_style` {#enforce_naming}

[`feature.enforce_naming_style`](/editions/features#enforce_naming) 会启用严格的命名风格强制执行，以确保 proto 默认可往返（round-trip）；同时提供一个可用于选择退出（opt-out）、改用旧式命名风格的特性值。

### `default_symbol_visibility` {#default_symbol}

该特性控制可导入符号（例如消息（message）和枚举（enum））的默认符号可见性（symbol visibility）为以下二者之一：

*   `export`：可被其他 proto 文件通过 import 语句引用
*   `local`：无法在当前文件之外被引用

版次 2024 中的默认特性值 `EXPORT_TOP_LEVEL` 确保顶层符号默认可导出，而嵌套符号默认为 local。

它可以与 [`export` 和 `local` 关键字](#export-local)（同样新增于版次 2024）配合使用，以显式标注符号可见性。

符号可见性仅控制哪些符号可以被其他 proto 文件导入，但不影响代码生成。

### C++：`enum_name_uses_string_view` {#enum_name}

以前，所有生成的枚举类型都提供以下函数，用于从枚举值获取其名称，而在运行时（runtime）构造 `std::string` 实例会产生显著开销：

```cpp
const std::string& Foo_Name(int);
```

版次 2024 中的默认特性值将此签名改为返回 `absl::string_view`，以实现更好的存储解耦，并可能节省内存/CPU 开销。

```cpp
absl::string_view Foo_Name(int);
```

用户应按照[迁移指南](/support/migration#string_view-return-type)迁移自己的代码，以处理新的返回类型。

更多信息请参阅[字符串视图 API](/reference/cpp/string-view)。

### Java：`nest_in_file_class` {#nest_in}

该特性控制 Java 生成器是否将生成的类嵌套在 Java 生成文件类中。

版次 2024 中的默认值会默认将各个类生成到各自独立的文件中，这也是此前 `java_multiple_files = true` 文件选项的默认行为。该特性取代了已在版次 2024 中移除的 `java_multiple_files`。

默认外层类名也更改为始终采用 `.proto` 文件名的驼峰命名（camel case）形式，并默认加上 Proto 后缀（例如 `foo/bar_baz.proto -> BarBazProto`）。你可以使用 `java_outer_classname` 文件选项覆盖这一默认值，取代版次 2024 之前视冲突情况而定的默认类名 `BarBaz` 或 `BarBazOuterClass`。

### Java：`large_enum` {#large_enum}

该特性允许创建大型 Java 枚举，突破由 Java 语言标准常量限制造成的枚举数量上限。

大型枚举默认不启用，但你可以使用该特性显式启用。请注意，该特性复刻了类枚举（enum-like）行为，但存在一些显著差异（例如不支持 switch 语句）。

## 语法变更 {#grammar-changes}

### `import option` {#import-option}

版次 2024 新增了对选项导入（option import）的支持，所用语法为 `import option`。

与普通的 `import` 语句不同，`import option` 只导入 `.proto` 文件中定义的自定义选项，不导入其他符号。

这意味着消息和枚举会被排除在选项导入之外。在下面的示例中，`Bar` 消息不能在 `foo.proto` 中用作字段（field）类型，但类型为 `Bar` 的选项仍可设置。

选项导入必须位于所有其他 `import` 语句之后。

示例：

```proto
// bar.proto
edition = "2024";

import "google/protobuf/descriptor.proto";

message Bar {
  bool bar = 1;
}

extend proto2.FileOptions {
  bool file_opt1 = 5000;
  Bar file_opt2 = 5001;
}
```

```proto
// foo.proto:
edition = "2024";

import option "bar.proto";

option (file_opt1) = true;
option (file_opt2) = {bar: true};

message Foo {
  // Bar bar = 1; // 这是不允许的
}
```

选项导入的符号无需生成代码（generated code），因此应当在 `proto_library` 中以 `option_deps`（而不是 `deps`）的形式提供。这样可以避免生成不可达的代码。

```build
proto_library(
  name = "foo",
  srcs = ["foo.proto"],
  option_deps = [":custom_option"]
)
```

在导入 Protobuf 语言特性和其他自定义选项时，强烈建议使用选项导入和 `option_deps`，以避免生成不必要的代码。

`option_deps` 需要 Bazel 8 或更高版本，因为 Bazel 7 中的 `native.proto_library` 不支持此功能。

它还取代了已在版次 2024 中被移除的 `import weak`。

### `export` / `local` 关键字 {#export-local}

版次 2024 新增了 `export` 和 `local` 关键字，作为可导入符号的符号可见性修饰符，用于在 [`default_symbol_visibility` 特性](/editions/features#symbol-vis)所指定默认行为的基础上进行调整。

它控制哪些符号可以被其他 proto 文件导入，但不影响代码生成。

在版次 2024 中，这些关键字默认可设置在所有消息和枚举符号上。不过，`default_symbol_visibility` 特性的某些取值会进一步限制哪些符号可以导出。

示例：

```proto
// 版次 2024 中，顶层符号默认导出
local message LocalMessage {
  // 版次 2024 中，嵌套符号默认为 local
  export enum ExportedNestedEnum {
    UNKNOWN_EXPORTED_NESTED_ENUM_VALUE = 0;
  }
}
```

### “import weak” 与 `weak` 字段选项 {#import-weak}

从版次 2024 开始，不再允许弱导入（weak import）。

此前大多数依赖 `import weak` 声明“弱依赖（weak dependency）”、从而在无需生成代码的情况下为 C++ 和 Go 导入自定义选项的用户，应改为迁移到 [`import option`](/editions/overview#import-option)。

### `ctype` 字段选项 {#ctype}

从版次 2024 开始，不再允许使用 `ctype` 字段选项。请改用 [`features.(pb.cpp).string_type`](/editions/features#string_type) 特性。

### `java_multiple_files` 文件选项 {#java_multiple}

`java_multiple_files` 文件选项已在版次 2024 中移除，由新的 [`features.nest_in_file_class`](/editions/features#java-nest_in_file) Java 特性取代。
