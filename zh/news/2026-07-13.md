## 版次 2026 {#edition-2026}

我们计划于 2026 年第三季度在 36.x 中向开源项目发布 Protobuf 版次（Editions）。

这些内容描述了我们所预期的变更实现方式，但由于软件本身具有灵活性，其中部分变更可能不会最终落地，或与本主题中的描述有所出入。

有关版次 2026（Edition 2026）的更多文档将发布在[版次特性设置（Feature Settings for Editions）](/editions/features)中，其中包括[迁移指南](/support/migration)。

## 现有特性的变更 {#changes-existing}

本节详细介绍其版次默认值（edition_default）将在版次 2026 中发生变更的现有特性。

### `enforce_naming_style`：`STYLE2026` {#enforce_naming_style}

`enforce_naming_style` 的特性默认值将更新为 `STYLE2026`，以减少常见的字段命名冲突。

示例：

*   在包含名为 `x` 的字段（field）的消息（message）中，以下字段名（field name）将被禁止：
    *   `has_x`
    *   `set_x`
    *   `get_x`
    *   `clear_x`
    *   `x_value`
*   字段不得命名为 `descriptor`

### `default_symbol_visibility`：`STRICT` {#default_symbol_visibility}

[https://protobuf.dev/programming-guides/symbol_visibility/](https://protobuf.dev/programming-guides/symbol_visibility/)

`default_symbol_visibility` 的特性默认值将更新为 `STRICT`，以鼓励显式使用 `export` 和 `local` 关键字，并默认禁止导出嵌套类型（nested types）。

该特性鼓励遵循 [1-1-1 最佳实践](/best-practices/1-1-1)中定义的最佳实践，该实践倡导让 .proto 文件保持精炼的定义范围，以限制依赖膨胀。

## 新特性 {#new-features}

本节详细介绍将在版次 2026 中引入的新特性。

### JSON 选项：值的自定义 JSON 字符串 {#json-custom-string}

版次 2026 为枚举（enum）值引入了一个新的 JSON 自定义字符串选项（option）。

在此之前，我们已通过 `json_name` 选项支持自定义键（key）。这一新选项将该行为扩展到了值（value）上。

进行重命名可能是为了避免冲突、辅助迁移，或满足外部要求。

用法示例：

```protobuf
enum FOO {
   ...
   FOO_BAR = 5 [(pb.enumvalue.json).string = "custom_string_here"];
   ...
}
```

### C++ 选项：命名空间（namespace）{#cpp-namespace}

版次 2026 引入了新的 C++ 选项 `namespace` 这一自定义选项，用于显式设置生成绑定的命名空间。

这使 C++ 开发者能够独立于 .proto 包（package）指定绑定语言的打包方式。

以新的 namespace C++ 选项为例：

```protobuf
import option "google/protobuf/cpp_options.proto";

package clock.time;

option (pb.file.cpp).namespace = "clock_time";
```

### C++ 选项：C++ 自定义选项从 `descriptor.proto` 中移出 {#cpp-custom-options}

在版次 2026 中，C++ 语言专属选项已从 `descriptor.proto` 移至独立的自定义选项文件。

要在版次 2026 中访问这些 C++ 自定义选项，请按如下方式导入 C++ 语言自定义选项：```protobuf
import option "google/protobuf/cpp_features.proto";

option features.(pb.cpp).repeated_type = PROXY
```

返回的代理（proxy）类型遵循 STL 容器命名约定。

目前 `RepeatedPtrField`/`RepeatedField` 上可用的某些方法将无法通过代理使用，例如 `AddAllocated`/`ReleaseLast`、data/mutable_data、`pointer_begin`/`pointer_end` 和 `GetArena`。

用法示例：

```cpp
// 之前：
google::protobuf::RepeatedPtrField<MyMessage>* rpf = message.mutable_repeated_message();
MyMessage* element1 = rpf->Add();
const MyMessage& element2 = rpf->Get(0);
MyMessage* element3 = rpf->Mutable(1);

// 之后：
google::protobuf::RepeatedFieldProxy<MyMessage> rpf = message.mutable_repeated_message();
MyMessage& element1 = rpf.emplace_back();
const MyMessage& element2 = rpf.get(0);
MyMessage& element2 = rpf[0];
```

`RepeatedFieldProxy` 没有公共构造函数（浅拷贝构造函数除外）。代理只能由消息内的可重复字段作为底层承载。为辅助迁移，我们引入了新类型 `RepeatedFieldOrProxy`，它既可以从 `RepeatedFieldProxy` 隐式转换而来，也可以从旧式的 `RepeatedPtrField`/`RepeatedField` 引用隐式转换而来；除此之外，它的接口与 `RepeatedFieldProxy` 完全相同。

### C#：新增可空引用类型（nullable reference types）的选项与代码生成 {#csharp-nullable}

版次 2026 新增了对生成使用可空引用类型的 C# 代码的支持。

该特性为可选启用（opt-in），以满足既有外部用户的请求。

## 语法变更 {#grammar-changes}

版次 2026 没有新增或移除任何语法。
