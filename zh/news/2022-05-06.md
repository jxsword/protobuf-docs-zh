## 版本机制 {#versioning}

我们更改了版本机制（versioning），以便能够更敏捷地更新 Protobuf 中各语言特定的部分。在新机制下，每种语言都拥有自己的主版本（major version），可独立于其他语言递增，本文后文将以 Python 发布（release）为例加以说明。不过，次版本（minor version）与补丁版本（patch version）仍将保持联动。这使我们能够向部分语言引入破坏性变更（breaking change），而无须在未出现破坏性变更的语言中提升主版本号。

这一新版本机制的首个实例是 Python API 的新版本 4.21.0，它接续前一个版本 3.20.1。其他语言的 API 将以 3.21.0 的形式发布。

## Python 更新 {#python-updates}

我们对 Protobuf 的 Python 语言支持做了一些变更。4.21.0 是一个新的主版本，接续 3.20.1。新版本基于 [upb 库](https://github.com/protocolbuffers/upb)，解析性能显著优于以往的发布，对大型载荷（payload）尤其明显。它还包含适用于 Apple silicon 的预构建二进制模块，无需手动构建即可获得更高的性能。

新的发布确实包含一些破坏性变更。具体如下：

*   [`UnknownFields()`](https://googleapis.dev/python/protobuf/3.17.0/google/protobuf/message.html#google.protobuf.message.Message.UnknownFields) 方法原先依赖一个隐式创建的类，现在由显式创建的 `UnknownFieldSet` 类取代。
*   一些非核心特性可能发生了变化，例如某些字符串或错误消息的具体格式。这些并不被视为破坏性变更，但仍可能影响你现有的代码库。
*   依赖在 Python 与 C++ 之间共享消息的应用在新版本中将无法正常工作。大多数开发者不会受此影响，但 [Nucleus](https://github.com/google/nucleus) 以及其他一些库的用户可能会受到影响。作为一种变通方案，你可以[设置一个环境变量](/reference/python/python-generated#sharing-messages)，强制该库保持兼容性。
*   Python upb 要求使用由 protoc 3.19.0 或更新版本所生成的代码（generated code）。

## JavaScript 支持 {#javascript}

我们为 Protobuf 的 JavaScript 支持做了一些调整，以便 JavaScript 能够独立于主仓库进行演进和发布。具体来说，我们将该语言支持从[主项目](https://github.com/protocolbuffers/protobuf)中解耦，并迁移到[其独立的仓库](https://github.com/protocolbuffers/protobuf-javascript)中。

如果你创建了任何与 Protobuf 的 JavaScript 支持相关、且仍希望合并的 pull request，欢迎在 JavaScript 仓库中重新提交这些请求。我们会自动转移 GitHub 议题（issue）。
