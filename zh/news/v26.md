以下公告专门针对 26.x 版本（version），该版本于 2024 年 3 月 13 日发布（release）。按时间顺序呈现的信息请参阅
[新闻](/news)。

## 一般变更

### JSON 格式化器选项变更 {#JSON}

从 26.x 系列开始，用于打印默认值（default value）字段（field）的 JSON 格式化器选项，被替换为一种统一处理 proto2 与 proto3 `optional` 字段的固定方式。

*   Java：`includingDefaultValueFields()` 被替换为
    `alwaysPrintFieldsWithNoPresence()`。
*   C++：`always_print_default_values` 被替换为
    `always_print_fields_with_no_presence=True`。
*   Py：`including_default_value_fields=True` 被替换为
    `always_print_fields_with_no_presence=True`。

新标志在 proto3 消息（message）上的行为与旧标志完全一致，但不再适用于 proto2 `optional` 字段。旧标志适用于 proto2 `optional` 字段，但不适用于 proto3 `optional` 字段。

### 对生成代码（gencode）/ 运行时（runtime）不匹配下毒丸

根据我们的[跨版本运行时保证](/support/cross-version-runtime-guarantee)，Protobuf 不支持跨主版本边界混用生成代码（generated code）与运行时，也不支持在同一主运行时版本内将较新版本 protoc 的生成代码与较旧的运行时混用。我们计划引入“毒丸（poison pill）”来检测并强制执行这些不允许的不匹配。

这不被视为破坏性变更（breaking change），因为它只是增加了对既有政策的强制执行，但可能需要用户更新其生成代码。

## C++ 破坏性变更

在 v26 中，按照[破坏性变更政策](/news/2022-07-06)和[版本支持政策](/support/version-support#cpp-tooling)，我们计划对 C++ 进行主版本升级。

以下章节列出了我们计划纳入 Protobuf 26.0 发布的破坏性变更集合。请注意，计划可能会而且确实会发生变化。这些是需要留意的潜在破坏性变更，但它们可能不会在这一次发布中发生，也可能根本不会发生。

### 移除 repeated 字段上已弃用（deprecated）的 clear API

以下已弃用的方法将被移除：

*   `RepeatedPtrField::ReleaseCleared()`
*   `RepeatedPtrField::ClearedCount()`
*   `RepeatedPtrField::AddCleared()`

### 移除 C++ 旧式 syntax 描述符（descriptor）API

随着[版次（edition）](/editions)的推出，业务逻辑不再支持 syntax。请改用 [`descriptor.h`](/reference/cpp/api-docs/google.protobuf.descriptor) 中定义的各种特性（feature）辅助方法来查询更有针对性的行为，例如 [`has_presence`](/reference/cpp/api-docs/google.protobuf.descriptor#FieldDescriptor.has_presence.details)，以便在 C++ 中查询特性。

### 移除已弃用的 syntax 访问器（accessor）

我们计划在 v26 中移除已弃用的 syntax 访问器 `FileDescriptor::Syntax`。我们建议改用 `FileDescriptor::edition` 提供的 getter。

### 移除已弃用的 SupportsUnknownEnumValues 方法

`SupportsUnknownEnumValues` 方法[已于 2023 年 3 月被弃用](https://github.com/protocolbuffers/protobuf/pull/12129)。我们计划在 v26 中将其移除。

### 移除 std::string 错误收集器覆盖方法

我们计划移除错误收集器中已弃用的 `std::string` 方法。

## Java 破坏性变更

在 v26 中，按照[破坏性变更政策](/news/2022-07-06)和[版本支持政策](/support/version-support#java)，我们计划对 Java 进行主版本升级。

以下章节列出了我们计划纳入 Protobuf 26.0 发布的破坏性变更集合。请注意，计划可能会而且确实会发生变化。这些是需要留意的潜在破坏性变更，但它们可能不会在这一次发布中发生，也可能根本不会发生。

### 破坏与旧生成代码的兼容性

v26.x 将破坏与来自较旧主版本的生成代码的兼容性。用户应重新生成旧的生成代码，使其来自相同版本。

例如，`GeneratedMessageV3` 最初是为了让来自 v2.x.x 的生成代码在 v3.x.x 运行时下保持向后兼容（backward compatibility）而引入的，它将被重命名为 `GeneratedMessage`。运行时将更新以支持[版次](/editions/overview/)，而后者与旧的生成代码不兼容。

这符合我们现有的[跨版本运行时保证](/support/cross-version-runtime-guarantee)，并且是一项破坏性变更。

### 移除已弃用的方法/变量

v26.x 将移除对已弃用方法和变量的访问。它们通常已在之前的发布中被标记为 `@Deprecated`。

这将移除对以下非穷尽列表的访问：

*   描述符 syntax API，应替换为相应的特性访问器（例如
    `FieldDescriptor.hasPresence()`、`EnumDescriptor.isClosed()`）

*   TextFormat 打印方法，应替换为相应的 `TextFormat.printer()` 方法。

*   PARSER 变量，应替换为 `parser()` 方法。

*   用于兼容旧 v2.x.x 生成代码的运行时方法。根据我们的
    [跨版本运行时保证](/support/cross-version-runtime-guarantee)，这已不再受支持。

更多详情将见相应的发布说明（release notes）。

## PHP 破坏性变更

26.x 系列计划进行以下变更：

*   在 setter 中为字符串字段验证 UTF-8。
*   移除通用服务（generic services）。（[提交 40ad3fa](https://github.com/protocolbuffers/protobuf/commit/40ad3fac603ba3c96e52a1266cd785a7adb8e3e4)）

## Python 破坏性变更

在 v26 中，按照[破坏性变更政策](/news/2022-07-06)和[版本支持政策](/support/version-support#python-support)，我们计划对 Python 进行主版本升级。

26.x 系列计划进行以下变更：

*   让 `str(msg)` 转义字符串字段中的任何无效 UTF-8。
*   让 `text_format.MessageToString()` 默认输出原始 UTF-8，同时转义任何无效的 UTF-8 序列。
*   修复时间戳边界（[提交 1250d5f](https://github.com/protocolbuffers/protobuf/commit/1250d5f6cccb0a45f959c7219980a0aad5060ee5)）

### 移除已弃用的 API

在 26.x 发布中，以下已弃用的 API 将被移除：

*   [`AddFileDescriptor`](https://googleapis.dev/python/protobuf/latest/google/protobuf/descriptor_pool.html#google.protobuf.descriptor_pool.DescriptorPool.AddFileDescriptor)
*   [`AddDescriptor`](https://googleapis.dev/python/protobuf/latest/google/protobuf/descriptor_pool.html#google.protobuf.descriptor_pool.DescriptorPool.AddDescriptor)
*   [`AddEnumDescriptor`](https://googleapis.dev/python/protobuf/latest/google/protobuf/descriptor_pool.html#google.protobuf.descriptor_pool.DescriptorPool.AddEnumDescriptor)
*   [`AddExtensionDescriptor`](https://googleapis.dev/python/protobuf/latest/google/protobuf/descriptor_pool.html#google.protobuf.descriptor_pool.DescriptorPool.AddExtensionDescriptor)
*   [`AddServiceDescriptor`](https://googleapis.dev/python/protobuf/latest/google/protobuf/descriptor_pool.html#google.protobuf.descriptor_pool.DescriptorPool.AddServiceDescriptor)

### 拒绝使用 None 可迭代对象扩展 repeated 字段

从 26.x 发布开始，用 `None` 可迭代对象扩展 repeated 字段将被拒绝（会抛出 `TypeError`）。例如，`m.repeated_int32.extend(None)` 将被拒绝。

### 移除消息类中的 RegisterExtension

从 26.x 发布开始，[`RegisterExtension`](https://googleapis.dev/python/protobuf/latest/google/protobuf/descriptor_pb2.html#google.protobuf.descriptor_pb2.DescriptorProto.ExtensionRange.RegisterExtension)
将被移除。在 Python 中，你可以使用消息对象上的 `Extensions` 属性来访问扩展（extension）。

这同时影响纯 Python 与 Python 的 C++ 实现，但不影响 upb Python。

### 从 GitHub 移除 `setup.py` 与 `setup.cfg` 支持

在 26.x 发布中，[GitHub 仓库](https://github.com/protocolbuffers/protobuf/tree/main/python)的 `python/` 目录以及 GitHub [发布压缩包](https://github.com/protocolbuffers/protobuf/releases)中将不再存在 `setup.py` 和 `setup.cfg`。这意味着将无法再直接从 GitHub 仓库或发布压缩包构建 Python 软件包。

[在 PyPI 上](https://pypi.org/project/protobuf/#files)发布的 Python 源码包*仍将*在顶层目录中包含 `setup.py`。对于不想使用我们在 PyPI 上分发的二进制包的用户，这是受支持且推荐的 Python 二进制包构建方式。

更多信息请参阅 [#15671](https://github.com/protocolbuffers/protobuf/pull/15671)。

### 时间戳会进行有效性检查

在 v26 中，系统会检查 `Timestamp` 值是否有效。秒必须位于 [-62135596800, 253402300799] 范围内，纳秒必须位于 [0, 999999999] 范围内。超出这些范围的值将抛出异常。

### 移除已弃用的 syntax 访问器

我们计划在 v26 中移除已弃用的 syntax 访问器 `FileDescriptor.syntax`，并计划在其位置新增 `FileDescriptor.edition`。

### 移除 UnknownFields 支持

在 v25 中，[`message.UnknownFields()`](https://googleapis.dev/python/protobuf/latest/google/protobuf/message.html#google.protobuf.message.Message.UnknownFields)
在纯 Python 与 C++ 扩展中已被弃用。我们计划在 v26 中将其移除。请使用 `unknown_fields.py` 中新的
[`UnknownFieldSet(message)`](https://googleapis.dev/python/protobuf/latest/google/protobuf/unknown_fields.html)
支持作为替代。

有关所有这些变更的更多详情将见相应的发布说明。

## Ruby 破坏性变更

*   修复 `RepeatedField#each_index`，使其具有正确的语义。（[#11767](https://github.com/protocolbuffers/protobuf/pull/11767)）
*   移除 Ruby DSL 及相关的兼容性代码，从而完成[4 月宣布的迁移](/news/2023-04-20)。
*   `Message#to_h` 修复：
    *   移除未设置的 oneof 字段。（[#6167](https://github.com/protocolbuffers/protobuf/issues/6167)）
    *   移除未设置的子消息字段
*   为 [`encode_json`](https://github.com/protocolbuffers/protobuf/blob/2fb0b93d9de226ea96f2dc2b4779eb4712d01d5c/ruby/ext/google/protobuf_c/message.c#L1118)/[`decode_json`](https://github.com/protocolbuffers/protobuf/blob/2fb0b93d9de226ea96f2dc2b4779eb4712d01d5c/ruby/ext/google/protobuf_c/message.c#L1004)
    使用消息的池。
*   移除已弃用的 syntax 访问器 `FileDescriptor.syntax`，并在其位置添加语义检查：
    *   `FieldDescriptor.has_presence`，用于测试字段是否具有存在性。
    *   `FieldDescriptor.is_packed`，用于测试 repeated 字段是否为紧凑编码。
    *   `FieldDescriptor.requires_utf8_validation`，用于测试字符串字段是否需要 UTF-8 校验。
    *   `EnumDescriptor.is_closed`，用于测试枚举是否为封闭式。

### Ruby 中的 freeze 现已递归生效

从 26.x 系列开始，应用 freeze 时将递归应用，影响所有子消息、映射与 repeated 字段。
