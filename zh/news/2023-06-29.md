**TL;DR:** 我们计划于 2023 年下半年向开源项目发布 Protobuf Editions（版次机制）。虽然在首次发布时并不要求从 proto2/proto3 语法迁移到 Editions 语法，但我们鼓励你在软件项目的未来规划中安排这次迁移。

## Protobuf Editions {#editions}

Protobuf Editions 取代了 Protobuf 一直以来使用的 proto2 和 proto3 标识。你无需再在 proto 定义文件顶部添加 `syntax = "proto2"` 或 `syntax = "proto3"`，而是使用版次（edition）编号（例如 `edition = "2024"`）来指定文件将具有的默认行为。版次机制让这门语言能够随时间推移逐步演进。

与旧版本中硬编码的行为不同，版次将表示一组“特性”，每个特性都带有一个默认值（即行为），你可以对其进行覆盖。特性（feature）是设置在文件、消息（message）、字段（field）、枚举（enum）等之上的选项（option），用于指定 protoc、代码生成器（code generator）以及 Protobuf 运行时（runtime）的行为。当你的需求与所选版次的默认行为不匹配时，你可以在这些不同层级（文件、消息、字段等）上显式覆盖所期望的行为。

版次机制不会破坏现有的二进制文件，首个版次带来的冲击也将微乎其微；它将确立基线，并把 proto2 和 proto3 的定义合并为一种全新的单一定义格式。它不需要你对代码做任何修改。我们将提供一个名为 Prototiller 的工具来迁移 .proto 文件。下面的示例展示了一个 proto2 定义文件和一个 proto3 文件，以及在使用 Prototiller 将它们转换为 Protobuf Editions 格式之后，各自可能呈现的样子：

<section class="tabs">

#### Proto2 语法 {.new-tab}

```proto
// proto2 文件
syntax = "proto2";

message Player {
  // 在 proto2 中，optional 字段具有显式存在性
  optional string name = 1;
  // proto2 仍支持有问题的 "required" 字段规则
  required int32 id = 2;
  // 在 proto2 中，该字段默认不采用 packed 编码
  repeated int32 scores = 3;

  enum Handed {
    HANDED_UNSPECIFIED = 0,
    HANDED_LEFT = 1,
    HANDED_RIGHT = 2,
    HANDED_AMBIDEXTROUS = 3,
  }

  // 在 proto2 中，枚举是封闭式的
  optional Handed handed = 4;
}
```

#### Editions 语法 {.new-tab}

```proto
// proto2 文件的 Editions 版本
edition = "2023";

message Player {
  string name = 1;
  int32 id = 2 [features.field_presence = LEGACY_REQUIRED];
  repeated int32 scores = 3 [features.repeated_field_encoding = EXPANDED];

  enum Handed {
    // 这会覆盖版次 2023 的默认行为，该默认行为是 OPEN
    option features.enum = CLOSED;
    HANDED_UNSPECIFIED = 0,
    HANDED_LEFT = 1,
    HANDED_RIGHT = 2,
    HANDED_AMBIDEXTROUS = 3,
  }

  Handed handed = 4;
}
```

</section>

<section class="tabs">

#### Proto3 语法 {.new-tab}

```proto
// proto3 文件
syntax = "proto3";

message Player {
  // 在 proto3 中，optional 字段具有显式存在性
  optional string name = 1;
  // 在 proto3 中，未指定字段规则时默认为隐式存在性
  int32 id = 2;
  // 在 proto3 中，该字段默认采用 packed 编码
  repeated int32 scores = 3;

  enum Handed {
    HANDED_UNSPECIFIED = 0,
    HANDED_LEFT = 1,
    HANDED_RIGHT = 2,
    HANDED_AMBIDEXTROUS = 3,
  }

  // 在 proto3 中，枚举是开放式的
  optional Handed handed = 4;
}
```

#### Editions 语法 {.new-tab}

```proto
// proto3 文件的 Editions 版本
edition = "2023";

message Player {
  string name = 1;
  int32 id = 2 [features.field_presence = IMPLICIT];
  repeated int32 scores = 3;

  enum Handed {
    HANDED_UNSPECIFIED = 0,
    HANDED_LEFT = 1,
    HANDED_RIGHT = 2,
    HANDED_AMBIDEXTROUS = 3,
  }

  Handed handed = 4;
}
```

</section>

尽管本主题中的示例展示的是将 proto2 和 proto3 直接转换为基于 Protobuf Editions 的等效表示，你也可以根据项目需求对这些设置进行混合搭配。

特性的生命周期由版次的发布来管理。例如，`features.awesome_new_feature` 可能会在版次 2031 中引入，其新行为将应用于所有未显式覆盖这一新行为的定义。到了版次 2033，这一新特性将被弃用（deprecated）。覆盖仍然有效，但开发者会收到提醒，需要尽快适配新行为。到了版次 2036，该特性被移除，新行为将应用于所有 proto 文件；此时已无法再覆盖新行为。
