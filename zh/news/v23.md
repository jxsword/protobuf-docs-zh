以下公告专门针对 23.x 版本（version），该版本于 2023 年 5 月 8 日发布（release）。按时间顺序呈现的信息请参阅
[新闻](/news)。

## Ruby 生成器的变更 {#ruby}

[这个 GitHub PR](https://github.com/protocolbuffers/protobuf/pull/12319) 将包含在 23.x 发布中，它把 Ruby 代码生成器（code generator）改为输出序列化的 proto，而不是 DSL。

此举从代码生成器中移除了 DSL，为日后将 DSL 拆分到独立的包中做准备。

给定如下 .proto 文件：

```proto
syntax = "proto3";

package pkg;

message TestMessage {
  optional int32 i32 = 1;
  optional TestMessage msg = 2;
}
```

此前生成的代码（generated code）：

```ruby
# 由 protocol buffer 编译器生成。请勿编辑！
# 来源：protoc_explorer/main.proto

require 'google/protobuf'

Google::Protobuf::DescriptorPool.generated_pool.build do
  add_file("test.proto", :syntax => :proto3) do
    add_message "pkg.TestMessage" do
      proto3_optional :i32, :int32, 1
      proto3_optional :msg, :message, 2, "pkg.TestMessage"
    end
  end
end

module Pkg
  TestMessage = ::Google::Protobuf::DescriptorPool.generated_pool.lookup("pkg.TestMessage").msgclass
end
```

此后生成的代码：

```ruby
# frozen_string_literal: true
# 由 protocol buffer 编译器生成。请勿编辑！
# 来源：test.proto

require 'google/protobuf'

descriptor_data = "\n\ntest.proto\x12\x03pkg\"S\n\x0bTestMessage\x12\x10\n\x03i32\x18\x01 \x01(\x05H\x00\x88\x01\x01\x12\"\n\x03msg\x18\x02 \x01(\x0b\x32\x10.pkg.TestMessageH\x01\x88\x01\x01\x42\x06\n\x04_i32B\x06\n\x04_msgb\x06proto3"
begin
  Google::Protobuf::DescriptorPool.generated_pool.add_serialized_file(descriptor_data)
rescue TypeError => e
  # <兼容性代码，见下文>
end

module Pkg
  TestMessage = ::Google::Protobuf::DescriptorPool.generated_pool.lookup("pkg.TestMessage").msgclass
end
```

此变更修复了此前存在的几乎所有一致性（conformance）问题。这是从 DSL（有损）迁移到可保留全部信息的序列化描述符（descriptor）所带来的附带效果。

### 向后兼容（backward compatibility） {#backward}

此变更应当与 Ruby Protobuf >= 3.18.0（2021 年 9 月发布）实现 100% 兼容。此外，它应当与所有现有用户和部署环境兼容。

为了达到这种级别的向后兼容，其中**确实**插入了一些特殊的兼容性代码，你应当对此有所了解。如果没有这些兼容性代码，存在一种可能破坏向后兼容的边界情况。旧代码在某些方面较为宽松，而新代码会更加严格。

使用完整的序列化描述符时，其中包含本文件所导入的全部 `.proto` 文件的列表（而 DSL 从未正确添加过依赖）。相关代码见
[`descriptor.proto`](https://github.com/protocolbuffers/protobuf/blob/dfb71558a2226718dc3bcf5df27cbc11c1f72382/src/google/protobuf/descriptor.proto#L65-L66)。

`add_serialized_file` 会验证描述符中列出的所有依赖此前是否已通过 `add_serialized_file` 添加。通常这应当没有问题，因为生成的代码会包含针对所有依赖的 Ruby `require` 语句，而且如果所依赖的类型此前未在 `DescriptorPool` 中定义，描述符反正也无法加载。

但如果文件路径存在歧义，就有可能出现问题。例如，考虑以下场景：

```proto
// foo/bar.proto

syntax = "proto2";

message Bar {}
```

```proto
// foo/baz.proto

syntax = "proto2";

import "bar.proto";

message Baz {
  optional Bar bar = 1;
}
```

如果像下面这样调用 `protoc`，它将正常工作：

```
$ protoc --ruby_out=. -Ifoo foo/bar.proto foo/baz.proto
$ RUBYLIB=. ruby baz_pb.rb
```

但如果像下面这样调用 `protoc`，且没有任何兼容性代码，加载将会失败：

```
$ protoc --ruby_out=. -I. -Ifoo foo/baz.proto
$ protoc --ruby_out=. -I. -Ifoo foo/bar.proto
$ RUBYLIB=foo ruby foo/baz_pb.rb
foo/baz_pb.rb:10:in `add_serialized_file': Unable to build file to DescriptorPool: Depends on file 'bar.proto', but it has not been loaded (Google::Protobuf::TypeError)
    from foo/baz_pb.rb:10:in `<main>'
```

问题在于 `bar.proto` 被两个不同的规范名称（canonical name）所引用：`bar.proto` 和 `foo/bar.proto`。这是用户错误：每个导入都应始终使用一致的完整路径来引用。希望这类用户错误会很少见，但不实际尝试很难知道。

此变更中的代码在检测到这种边界情况发生时，会使用 `warn` 打印一条警告：

```
$ RUBYLIB=foo ruby foo/baz_pb.rb
Warning: Protobuf detected an import path issue while loading generated file foo/baz_pb.rb
- foo/baz.proto imports bar.proto, but that import was loaded as foo/bar.proto
Each proto file must use a consistent fully-qualified name.
This will become an error in the next major version.
```

这种情况有两种可行的修复方法。其一是让导入始终使用名称 `bar.proto`（移除 `-I.`）。其二是让导入始终使用名称 `foo/bar.proto`（将导入行改为 `import "foo/bar.proto"` 并移除 `-Ifoo`）。

我们计划在下一个主版本中移除这段兼容性代码。

## 停止支持 Bazel <5.3 {#bazel}

v23 将停止支持 Bazel 4。Protobuf 将继续支持 Bazel 5 LTS，最低要求版本为 Bazel 5.3。这遵循
[基础 C++ 支持政策（Foundational C++ Support Policy）](https://opensource.google/documentation/policies/cplusplus-support#build_systems)
中描述的构建支持政策，也体现在
[基础 C++ 支持（Foundational C++ Support）](https://github.com/google/oss-policies-info/blob/main/foundational-cxx-support-matrix.md)
所列的版本中。

## 语法反射（reflection）的弃用 {#deprecation}

v23 将弃用通过反射检查语法版本的能力。该弃用（deprecation）将在构建时以警告的形式体现。该能力将在未来的发布中移除。
