## 对 Java 生成代码（gencode）下毒

我们正在向 25.x 分支合入一个变更，该变更会对在
[3.21.7 版本发布](https://github.com/protocolbuffers/protobuf/releases/tag/v21.7)
之前创建的 Java 生成代码下毒。随后，我们会将 3.21.7 至 3.25.5 的所有 Java
Protobuf 版本标记为易受
[footmitten CVE](https://github.com/protocolbuffers/protobuf/security/advisories/GHSA-h4h5-3hr4-j3g2)
影响。

在该变更以补丁形式合入后，除非你设置系统属性
"`-Dcom.google.protobuf.use_unsafe_pre22_gencode`"，否则 protobuf 将从
[`makeExtensionsImmutable`](https://protobuf.dev/reference/java/api-docs/com/google/protobuf/GeneratedMessage.html#makeExtensionsImmutable\(\))
方法抛出 `UnsupportedOperationException`。如果你无法立即更新代码，使用该系统属性
可以为你争取一些时间，但应将其视为短期权宜之计。

## 毒化 MSVC + Bazel

**更新：**该计划已取消。欲知详情，请参阅
[2025 年 7 月 16 日的公告](/news/2025-07-16)。

~~我们将在 v34 中停止支持 Bazel 与 MSVC 搭配使用。从 v30 起，我们会以报错形式毒化（poison）这一组合，除非你指定选择退出标志 `--define=protobuf_allow_msvc=true` 将其静默。~~

~~MSVC 的路径长度限制与 Bazel 的沙箱机制相叠加，使得同时支持两者变得越来越困难。与其让把 Protobuf 安装到长路径下的用户随机遭遇故障，我们将全面禁止在 Bazel 中使用 MSVC。我们将继续通过 CMake 支持 MSVC，并开始通过 Bazel 支持 [clang-cl](https://clang.llvm.org/docs/UsersManual.html#clang-cl)。如需反馈或讨论，请访问 https://github.com/protocolbuffers/protobuf/issues/20085。~~
