## 现有特性的变更

本节详细介绍哪些现有特性（feature）的默认设置将在版次 2024（Edition 2024）中发生变更。

### C++ string_type {#string_type}

`string_type` 特性的默认值最初发布于版次 2023，将在版次 2024 中从 `STRING` 变更为 `VIEW`。

有关此特性及其特性值（feature value）的更多信息，请参阅
[`features.(pb.cpp).string_type`](/editions/features#string_type)
和[字符串视图（string view）API](/reference/cpp/string-view)。

## 新特性 {#new-features}

本节详细介绍将在版次 2024 中引入的新特性。

### `enforce_naming_style` {#enforce_naming}

[`feature.enforce_naming_style`](/editions/features#enforce_naming)
会启用严格的命名风格强制检查，以确保 proto 默认可往返（round-trip），并提供一个特性值用于选择退出、改用旧版命名风格。

### `default_symbol_visibility` {#default_symbol}

该特性控制可导入符号（例如消息（message）和枚举（enum））的默认符号可见性为以下二者之一：

*   `export`：可通过 import 语句从其他 proto 引用
*   `local`：在当前文件之外不可引用

版次 2024 中的默认特性值 `EXPORT_TOP_LEVEL` 确保顶层符号默认为导出（export），而嵌套符号默认为本地（local）。

它可以与 [`export` 和 `local` 关键字](#export-local)配合使用来显式标注符号可见性；这些关键字同样是在版次 2024 中新增的。

符号可见性只控制其他 proto 文件可以导入哪些符号，不影响代码生成。

### C++：`enum_name_uses_string_view` {#enum_name}

此前，所有生成的枚举类型都提供以下函数来获取枚举值对应的标签，而该函数在运行时（runtime）构造 `std::string` 实例会产生显著开销：

```cpp
const std::string& Foo_Name(int);
```

版次 2024 中的默认特性值会将该签名迁移为返回 `absl::string_view`，从而实现更好的存储解耦，并有可能节省内存和 CPU 开销。

```cpp
absl::string_view Foo_Name(int);
```

用户应按照[迁移指南](/support/migration#string_view-return-type)迁移自己的代码，以处理新的返回类型。

更多信息请参阅[字符串视图 API](/reference/cpp/string-view)。

### Java：`nest_in_file_class` {#nest_in}

该特性控制 Java 生成器是否会把生成的类嵌套在 Java 生成的文件类中。

版次 2024 中的默认值会让类默认生成在各自的文件中，这也是此前 `java_multiple_files = true` 文件选项（file option）的默认行为。该特性取代了 `java_multiple_files`，后者在版次 2024 中已被移除。

默认的外层类名也会更新为：默认始终使用驼峰命名（camel case）的 `.proto` 文件名并加上 Proto 后缀（例如 `foo/bar_baz.proto -> BarBazProto`）。你可以使用 `java_outer_classname` 文件选项覆盖这一行为，以取代版次 2024 之前的默认值 `BarBaz` 或 `BarBazOuterClass`（取决于是否存在冲突）。

### Java：`large_enum` {#large_enum}

该特性允许创建大型 Java 枚举，突破 Java 语言标准常量数量限制所带来的枚举上限。

大型枚举的创建默认不启用，但你可以使用该特性显式启用。请注意，该特性复刻了类似枚举的行为，但存在一些显著差异（例如不支持 switch 语句）。

## 语法变更 {#grammar-changes}

### `import option` {#import-option}

版次 2024 通过 `import option` 语法增加了对选项导入（option import）的支持。

与普通的 `import` 语句不同，`import option` 只导入 `.proto` 文件中定义的自定义选项，而不导入其他符号。

这意味着消息和枚举会被排除在选项导入之外。在下面的示例中，`Bar` 消息不能在 `foo.proto` 中用作字段（field）类型，但类型为 `Bar` 的选项仍然可以设置。

选项导入还必须放在所有其他 import 语句之后。

示例：

```proto
// bar.proto
edition = "2024";

import "google/protobuf/descriptor.proto";

message Bar {
  bool bar = 1;
}

extend proto2.FileOptions {
  bool file_opt1 = 5000;
  Bar file_opt2 = 5001;
}
```

```proto
// foo.proto:
edition = "2024";

import option "bar.proto";

option (file_opt1) = true;
option (file_opt2) = {bar: true};

message Foo {
  // Bar bar = 1; // 这是不允许的
}
```

选项导入不需要为其符号生成代码（generated code），因此必须在 `proto_library` 中以 `option_deps` 而非 `deps` 的形式提供。这样可以避免生成不可达的代码。

```build
proto_library(
  name = "foo",
  srcs = ["foo.proto"],
  option_deps = [":custom_option"]
)
```

在导入 Protobuf 语言特性和其他自定义选项时，强烈建议使用选项导入和 `option_deps`，以避免生成不必要的代码。

`option_deps` 需要 Bazel 8 或更高版本，因为 Bazel 7 中的 `native.proto_library` 不支持此功能。

它还取代了 `import weak`，后者在版次 2024 中已被移除。

### `export` / `local` 关键字 {#export-local}

`export` 和 `local` 关键字在版次 2024 中加入，用作可导入符号可见性的修饰符；默认行为由
[`default_symbol_visibility` 特性](/editions/features#symbol-vis)指定。

它控制其他 proto 文件可以导入哪些符号，但不影响代码生成。

在版次 2024 中，这些关键字默认可以设置在所有消息和枚举符号上。不过，`default_symbol_visibility` 特性的某些取值会进一步限制哪些符号可以导出。

示例：

```proto
// 在版次 2024 中，顶层符号默认导出
local message LocalMessage {
  // 在版次 2024 中，嵌套符号默认为 local
  export enum ExportedNestedEnum {
    UNKNOWN_EXPORTED_NESTED_ENUM_VALUE = 0;
  }
}
```

### “import weak” 与 `weak` 字段选项 {#import-weak}

自版次 2024 起，不再允许弱导入（weak import）。

对于 C++ 和 Go，此前大多数依赖 `import weak` 声明“弱依赖”（weak dependency）、以便在不生成代码的情况下导入自定义选项的用户，应改为使用
[`import option`](/editions/overview#import-option)。

### `ctype` 字段选项 {#ctype}

自版次 2024 起，不再允许使用 `ctype` 字段选项。请改用
[`features.(pb.cpp).string_type`](/editions/features#string_type)
特性。

### `java_multiple_files` 文件选项 {#java_multiple}

`java_multiple_files` 文件选项在版次 2024 中被移除，由新的
[`features.nest_in_file_class`](/editions/features#java-nest_in_file)
Java 特性取代。
