<ul>
  <li>你对"内存泄漏"采用了严苛的定义，即要求每一次 malloc() 都有与之对应的 free()，哪怕是存活到程序退出的对象也不例外。</li>
  <li>你正在编写一个动态加载的库，需要在库被卸载时自行清理。</li>
</ul>

<p>多次调用此方法是安全的。然而，在 <a href='#ShutdownProtobufLibrary'>ShutdownProtobufLibrary()</a> 被调用之后，再使用 Protobuf 库的任何其他部分都是不安全的。此外，此调用不是线程安全的，用户需要自行对多次调用进行同步。 </p>
</div><h2 id="MessageLite">class MessageLite</h2><p><code>#include &lt;<a href="#">google/protobuf/message_lite.h</a>&gt;<br>namespace <a href="#google.protobuf">google::protobuf</a></code></p><p>轻量级协议消息的接口。 </p><p>所有协议消息对象都实现了此接口。非 lite 消息还会额外实现 <a href='google.protobuf.message#Message'>Message</a> 接口，后者是 <a href='#MessageLite'>MessageLite</a> 的子类。当你只需要它所支持的特性（feature）子集时——也就是任何不使用描述符（descriptor）或反射（reflection）的内容——应改用 <a href='#MessageLite'>MessageLite</a>。你可以在 .proto 文件中添加下面这一行，指示协议编译器生成只实现 <a href='#MessageLite'>MessageLite</a>、而不实现完整 <a href='google.protobuf.message#Message'>Message</a> 接口的类：</p>

<pre>option optimize_for = LITE_RUNTIME;</pre>

<p>在完整 Protobuf 运行时（runtime）库过于庞大的资源受限系统上，这一点尤其有用。</p>

<p>请注意，在非受限系统（例如服务器）上，当你需要链接大量协议定义时，减少总代码占用的更好方法是使用 optimize_for = CODE_SIZE。这会让生成代码（generated code）更小，同时仍支持完全相同的特性（以速度为代价）。当你只有少量消息（message）类型链接进二进制文件时，optimize_for = LITE_RUNTIME 才是最佳选择，此时 Protobuf 运行时本身的大小才是最大的问题。</p>

<p>用户不得从此类派生。只有协议编译器和内部库才允许创建其子类。 </p>
