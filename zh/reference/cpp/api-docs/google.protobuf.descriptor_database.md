</div><h2 id="SimpleDescriptorDatabase">class SimpleDescriptorDatabase: public <a href="#DescriptorDatabase">DescriptorDatabase</a></h2><p><code>#include &lt;<a href="#">google/protobuf/descriptor_database.h</a>&gt;<br>namespace <a href="#google.protobuf">google::protobuf</a></code></p><p>一种可以向其中手动插入文件的 <a href='#DescriptorDatabase'>DescriptorDatabase</a>。 </p><p><a href='#SimpleDescriptorDatabase.FindFileContainingSymbol'>FindFileContainingSymbol()</a> 已被完整实现。当你添加一个文件时，其中的符号会被建立索引以支持该功能。请注意，该实现可能返回误报，但仅限于该符号不可能定义在任何其他文件中的情形。具体来说，如果某个文件定义了符号 "Foo"，那么搜索 "Foo.[anything]" 就会匹配该文件。这样，数据库就不必激进地为符号的所有子符号建立索引。</p>

<p><a href='#SimpleDescriptorDatabase.FindFileContainingExtension'>FindFileContainingExtension()</a> 已大部分实现。当且仅当定义该扩展的原始 FieldDescriptorProto 在其 "extendee" 字段（field）中使用的是完全限定的类型名（即以 '.' 开头）时，它才能正常工作。如果 extendee 是一个相对名称，<a href='#SimpleDescriptorDatabase'>SimpleDescriptorDatabase</a> 就不会尝试解析该类型，因此它不会知道该扩展扩展的是什么类型。所以，用该扩展的包含类型去调用 <a href='#SimpleDescriptorDatabase.FindFileContainingExtension'>FindFileContainingExtension()</a> 时，实际上永远找不到该扩展。请注意，这是一个不太可能遇到的问题，因为协议编译器创建的所有 FileDescriptorProto（以及通过调用 <a href='google.protobuf.descriptor#FileDescriptor.CopyTo'>FileDescriptor::CopyTo()</a> 创建的那些）对所有类型都总是使用完全限定名称。只有当你自行构造 FileDescriptorProto，或者直接调用 <a href='google.protobuf.compiler.parser#Parser'>compiler::Parser</a> 时才需要担心。 </p>
