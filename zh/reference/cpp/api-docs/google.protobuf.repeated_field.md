<p><code>#include &lt;google/protobuf/repeated_field.h&gt;<br>namespace <a href="#google.protobuf">google::protobuf</a></code></p><p><a href='#RepeatedField'>RepeatedField</a> 与 <a href='#RepeatedPtrField'>RepeatedPtrField</a> 由生成的协议消息（message）类用于操作可重复字段（repeated field）。 </p><p>这两个类与 STL 的 vector 非常相似，但包含了许多被证明在 Protobuf 场景下特别有用的优化。<a href='#RepeatedPtrField'>RepeatedPtrField</a> 与 STL vector 的差异尤其明显，因为它管理着其所含指针的所有权。</p>

<p>通常，客户端无需直接访问 <a href='#RepeatedField'>RepeatedField</a> 对象，而应使用由协议编译器自动生成的访问器（accessor）函数。 </p>

</div> <hr><h3 id="RepeatedPtrField.ExtractSubrange.details"><code>void RepeatedPtrField::ExtractSubrange(<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;int start,<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;int num,<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;Element ** elements)</code></h3><div style="margin-left: 16px"><p>提取索引位于 "[start .. start+num-1]" 区间内的元素。 </p><p>调用者取得被提取元素的所有权，并负责在这些元素不再需要时将其删除。为方便调用者，如果 "elements" 非 NULL，指向被提取元素的指针会存入 "elements[0 .. num-1]"。如果 "elements" 为 NULL，调用者必须使用其他机制对这些元素执行任何后续操作（例如删除）。注意：实现还会移动索引位于 [start+num ..] 的元素。在循环内调用此例程可能导致平方级的性能问题。</p>
