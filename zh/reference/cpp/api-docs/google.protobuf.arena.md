</div><h2 id="Arena">class Arena</h2><p><code>#include &lt;<a href="#">google/protobuf/arena.h</a>&gt;<br>namespace <a href="#google.protobuf">google::protobuf</a></code></p><p><a href='#Arena'>Arena</a> 分配器。 </p><p><a href='#Arena'>Arena</a> 分配用 new/delete 取代普通的（基于堆的）分配方式，它把多次分配聚合为更大的块并在销毁时一次性释放全部分配，从而提升性能。协议消息（message）通过下文的 Arena::CreateMessage&lt;T&gt;(Arena*) 在 arena 上分配，并在 arena 被销毁时自动释放。</p>

<p>这是一个线程安全的实现：多个线程可以并发地从 arena 分配内存。销毁操作不是线程安全的，执行销毁的线程必须先与 arena 的使用者同步。</p>

<p>arena 提供两种分配接口：CreateMessage&lt;T&gt;，适用于启用了 arena 的 proto2 消息类型以及其他满足相应协议（见下文）的类型；以及 Create&lt;T&gt;，适用于任意类型 T。当类型 T 支持时，CreateMessage&lt;T&gt; 是更好的选择，因为该接口 (i) 会把 arena 指针传给被创建的对象，使其子对象与内部分配也能使用该 arena，并且 (ii) 会在可能的情况下省略对象的析构函数调用。Create&lt;T&gt; 对类型 T 没有任何特殊要求，并会在 arena 被销毁时调用对象的析构函数。</p>

<p><a href='#Arena.CreateMessage'>CreateMessage&lt;T&gt;(Arena* arena, Args&amp;&amp;... args)</a> 所要求的 arena 消息分配协议如下：</p>

<ul>
  <li>类型 T 必须（至少）拥有两个构造函数：一个可以用 <code>args</code>（不带 <code>arena</code>）调用的构造函数，在 T 分配于堆上时被调用；另一个可以用 <code>Arena* arena, Args&amp;&amp;... args</code> 调用的构造函数，在 T 分配于 arena 上时被调用。如果第二个构造函数以 NULL 的 arena 指针被调用，其效果必须等价于调用第一个（仅 <code>args</code>）构造函数。</li>
  <li>类型 T 必须拥有一个特定的 type trait：一个嵌套类型（nested type）|InternalArenaConstructable_|。它通常是指向 |void| 的 typedef。如果不存在这样的 type trait，那么实例化 CreateMessage&lt;T&gt; 将无法通过编译。</li>
  <li>类型 T <i>可以</i>拥有 type trait |DestructorSkippable_|。如果类型中存在该 type trait，则当且仅当它被传入非 NULL 的 arena 指针时，才不会调用其析构函数。如果类型上不存在该 type trait，那么在包含它的 arena 被销毁时，其析构函数总是会被调用。</li>
</ul>

<p>所有启用了 arena 的 proto2 消息类，以及 <a href='../google.protobuf.repeated_field#RepeatedPtrField'>RepeatedPtrField</a> 和 <a href='../google.protobuf.map#Map'>Map</a> 这类 Protobuf 容器类型，都实现了该协议。该协议属于 Protobuf 内部实现，不保证稳定。非 proto 类型不应依赖此协议。 </p>
