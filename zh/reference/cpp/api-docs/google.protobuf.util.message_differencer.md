</div><h2 id="MessageDifferencer">class MessageDifferencer</h2><p><code>#include &lt;<a href="#">google/protobuf/util/message_differencer.h</a>&gt;<br>namespace <a href="#google.protobuf.util">google::protobuf::util</a></code></p><p>一个基础差异比较器，可用于确定两个指定的 Protocol 消息之间的差异。 </p><p>如果发现任何差异，Compare 方法将返回 false，并且通过 ReportDifferencesTo 指定的任何差异比较器报告器都会被调用其报告方法（报告的实现见下文）。本类源自 //net/proto/protocol-differencer.h 中最初的 ProtocolDifferencer 实现（感谢 Todd！）。</p>
<p><a href='#MessageDifferencer'>MessageDifferencer</a> 要求被比较的消息必须是同一类型——即共享同一描述符的消息。否则，该类的行为是未定义的。</p>
<p>当被要求比较具有不同描述符的消息时，<a href='#MessageDifferencer'>MessageDifferencer</a> 应当如何处理，人们对此看法不一。有人认为它应当总是返回 false；也有人期望它尝试寻找相似的字段并照样进行比较 &ndash; 尤其是在描述符恰好完全相同的情况下。如果我们选择其中任何一种行为，总会有人觉得意外，并可能在没有意识到自己错误的情况下，编写出依赖另一种行为的代码。因此，我们禁止这种用法。</p>
<p>该类基于 proto2 反射（reflection）实现。对于常规用法，性能应当足够好。但在性能极其敏感的场合，有几种替代方案：</p>
<ul>
  <li>比较序列化（serialization）后的字符串。缺点：存在假阴性（有些消息其实相同，但它们的序列化字符串不同）。</li>
  <li>由编译器插件（plugin）提供 Equals 代码生成器（code generator）（net/proto2/contrib/equals_plugin）。缺点：生成代码（generated code）更多；附加规则会带来维护开销（必须与原始 proto_library 保持同步）。</li>
</ul>
<p>关于 google.protobuf.Any 的处理说明：<a href='#MessageDifferencer'>MessageDifferencer</a> 会自动把 Any::value 中保存的值（value）解包为一个 <a href='google.protobuf.message#Message'>Message</a>，并比较其中的各个字段。以 repeated Any 编码的消息无法使用 TreatAsMap 进行比较。</p>
<p>关于线程安全的说明：<a href='#MessageDifferencer'>MessageDifferencer</a> <i>不是</i>线程安全的。若要在多个线程中使用同一个 <a href='#MessageDifferencer'>MessageDifferencer</a> 实例，需要用锁加以保护。并发调用静态比较方法（例如 <a href='#MessageDifferencer.Equals'>MessageDifferencer::Equals</a>）没有问题，但对于性能关键的代码不建议这样做，因为它会导致额外的内存分配。 </p>
